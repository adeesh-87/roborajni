# Unity + CMock + Ceedling — quick reference (C only)

Always copy includes and structure from an existing test in the repo first.

## Minimal test file `test/test_sensor.c`
```c
#include "unity.h"
#include "sensor.h"        // module under test (Ceedling links sensor.c automatically)
#include "mock_spi.h"      // CMock generates mock_spi.c/.h from spi.h

void setUp(void)    { sensor_init(); }     // runs before EACH test in this file
void tearDown(void) { }                     // runs after EACH test

void test_Read_BusError_ReturnsMinusOne(void)
{
    spi_read_ExpectAndReturn(0x10, -5);
    TEST_ASSERT_EQUAL_INT(-1, sensor_read(0x10));
}
```
Test functions must be `void test_xxx(void)`. Without Ceedling a runner is needed:
generated by `ruby unity/auto/generate_test_runner.rb test_sensor.c` or hand-written:
```c
int main(void) { UNITY_BEGIN(); RUN_TEST(test_Read_BusError_ReturnsMinusOne); return UNITY_END(); }
```

## Assertions (expected first, then actual)
| Macro | Use |
|-------|-----|
| `TEST_ASSERT_TRUE(c)`, `TEST_ASSERT_FALSE(c)` | booleans |
| `TEST_ASSERT_EQUAL_INT(e, a)`, `_INT8/16/32`, `_UINT`, `_UINT8/16/32`, `_size_t` | integers by width |
| `TEST_ASSERT_EQUAL_HEX8/16/32(e, a)` | registers, bit patterns (prints hex) |
| `TEST_ASSERT_BITS(mask, e, a)`, `TEST_ASSERT_BIT_HIGH(bit, a)`, `_BIT_LOW` | bits |
| `TEST_ASSERT_NULL(p)`, `TEST_ASSERT_NOT_NULL(p)`, `TEST_ASSERT_EQUAL_PTR(e, a)` | pointers |
| `TEST_ASSERT_EQUAL_STRING(e, a)`, `_STRING_LEN(e, a, n)` | strings |
| `TEST_ASSERT_EQUAL_MEMORY(e, a, len)` | buffers, structs |
| `TEST_ASSERT_EQUAL_INT_ARRAY(e, a, n)`, `_UINT8_ARRAY`, `_HEX8_ARRAY` | arrays |
| `TEST_ASSERT_INT_WITHIN(delta, e, a)`, `TEST_ASSERT_FLOAT_WITHIN(delta, e, a)` | ranges, floats |
| `TEST_ASSERT_GREATER_THAN(threshold, a)`, `_LESS_THAN` | comparisons |
| `TEST_FAIL_MESSAGE("x")`, `TEST_IGNORE()`, any macro + `_MESSAGE(..., "x")` | messages |

## CMock — generated functions for `int spi_read(uint8_t reg);` and `void spi_write(uint8_t reg, const uint8_t* buf, size_t len);`
| Call | Meaning |
|------|---------|
| `spi_read_ExpectAndReturn(0x10, 42)` | expect one call with these args, return 42 |
| `spi_write_Expect(0x11, buf, 3)` | void function; pointer args compare the pointed-to data (default) |
| `adc_get_ExpectWithArrayAndReturn(ptr, 4, 0)` | compare `4` elements at ptr: each pointer arg gets a `<name>_Depth` arg after it (plugin `:array`). If the header pairs the pointer with a size parameter such as `len`/`size`, CMock uses that instead and there is NO depth arg |
| `spi_read_IgnoreAndReturn(42)` | any number of calls, any args (plugin `:ignore`) |
| `spi_write_ExpectAnyArgs()` / `spi_read_ExpectAnyArgsAndReturn(42)` | one call, args not checked (plugin `:expect_any_args`) |
| `spi_write_IgnoreArg_buf()` | after an Expect: do not check this arg (plugin `:ignore_arg`) |
| `adc_get_ReturnThruPtr_value(&v)` | after an Expect: write `v` into out-param `value` (plugin `:return_thru_ptr`) |
| `..._ReturnArrayThruPtr_buf(src, n)`, `..._ReturnMemThruPtr_buf(src, size)` | out-buffers |
| `spi_read_StubWithCallback(my_cb)` (newer: `_Stub`, `_AddCallback`) | own implementation; cb gets args + `int cmock_num_calls` (plugin `:callback`) |
Expectations are checked automatically at the end of each test. Several expectations of the SAME
function must come in order. Order across DIFFERENT functions is only checked with
`:enforce_strict_ordering: true` in the CMock config.
Plugins must be enabled in `project.yml` under `:cmock: :plugins:` (a YAML block list, one `- :plugin` per line).
**Before using a generated function, open the generated `mock_<header>.h` and copy the exact macro
and its parameters** (build once to generate it; Ceedling puts it under `build/test/mocks/`).
Never edit generated `mock_*.c/.h`: change the header or `project.yml` and rebuild.

## Ceedling
```sh
ceedling test:all                 # all tests
ceedling test:sensor              # test/test_sensor.c only
ceedling test:pattern[sensor]     # regex on file names
ceedling gcov:all                 # coverage (gcov plugin enabled in project.yml)
ceedling clobber                  # full clean
```
- Ceedling finds sources by the `#include "x.h"` in the test: it links `x.c` if found, and generates a
  mock for every `#include "mock_x.h"`. Extra sources: `TEST_SOURCE_FILE("x.c")` (Ceedling 1.x)
  or `TEST_FILE("x.c")` (0.3x). Check the Ceedling version in the repo.
- Test files are `test_*.c` under the test path(s) in `project.yml` (`:paths: :test:`).
- Output: `build/test/...`, gcov reports under `build/artifacts/gcov/` (location depends on version/config).

## Output
Per test: `test/test_sensor.c:12:test_Read_BusError_ReturnsMinusOne:PASS` or
`...:FAIL: Expected -1 Was 0`. Mock failures look like
`test_sensor.c:32:test_x:FAIL: Expected 0x11 Was 0x10:Function spi_read Argument reg:Function called with unexpected argument value.`
Summary: `4 Tests 1 Failures 0 Ignored` then `FAIL` or `OK`. Find failures: `grep -n ':FAIL' <run log>`. Ceedling prints an overall summary
`TESTED / PASSED / FAILED / IGNORED`.

## Errors and fixes
| Message | Fix |
|---------|-----|
| `Function x:Called more times than expected.` / `...fewer times...` | wrong number of Expect calls or wrong path |
| `Called earlier than expected` / `Called later than expected` | strict ordering is on and call order differs |
| `Function x Argument y:Function called with unexpected argument value.` | argument mismatch: fix the value, or `IgnoreArg_y` if the arg does not matter |
| `macro "x_ExpectWithArray..." passed 4 arguments, but takes just 3` | read the generated macro in `mock_*.h`; a size param may replace `_Depth` |
| `undefined reference` to a function of another module | add `#include "mock_other.h"` (or `other.h` for the real one) |
| `multiple definition` | test includes both `other.h` and `mock_other.h` sources: pick one |
| `x_ReturnThruPtr_...` undeclared | plugin `:return_thru_ptr` not enabled |
